# Публичный сайт Norocel

## Краткий отчёт по ТЗ

1. Поддомен: `https://norocel.noros.net`. Публичная главная — `/ru`, также `/ro` и `/en`; финансовый кабинет — `/app`. HTTP перенаправляется на HTTPS средствами Timeweb. Используется существующий Let's Encrypt с автопродлением.
2. Созданы главная, возможности, о продукте, Privacy, Terms, блог, три статьи и 404. Все основные страницы и статьи переведены на RU/RO/EN. Иллюстрации показывают демонстрационные суммы, а тексты описывают существующие функции приложения.
3. Используются существующие `noros/core` и `noros/cms`: модели Page/Post/Menu/Setting, переводы, BlockRegistry, SiteNavigation, ContentSeo, SafeHtml, sitemap/robots, роли и стандартная Filament CMS. Исходники пакетов не изменены. Снимки существующих пакетов находятся в `public-site/packages`: core `487f693f48daccacc961281a2e08f8b30a4de901`, CMS `2159f88d88d3660647b9f4b4bca38741f9a06b1b`.
4. Добавлены компоненты темы: общий layout, меню, переключение языка, SVG-иконки, карточки статей и демонстрационные экраны продукта. Существующие типы hero/text_image/advantages/cta/content/latest_posts получают представления и редактируемые схемы темы. Дизайн хранится в `public-site/resources/views` и `public-site/public/site`.
5. Контент редактируется в `/cms`: «Страницы», «Блог», «Меню», «Переводы». Вход — существующими учётными данными подтверждённого владельца приложения. У CMS отдельные база и сессия. Повторный seeder сохраняет правки редактора.
6. SEO отдельной страницы/статьи — в её форме; общие SEO, OpenGraph, sitemap/robots — «SEO сайта». Контакт, название и ссылки — «Настройки», ключи `site.contact_email`, `site.name`, `site.login_url`, `site.register_url`, `site.app_url`, `site.platform_label`, `site.platform_url`, `site.social_image`. В JSON-поле строка вводится в кавычках, например `"contact@noros.net"`. Начальное значение контакта — `contact@noros.net`, подпись — `Powered by Noros`.
7. Обязательные пункты ТЗ реализованы. Возможные дальнейшие работы: новые статьи, собственные изображения редактора и подключение аналитики по отдельному запросу. Аналитика сейчас не установлена.

## Устройство и запуск

Приложение финансов остаётся Laravel 12 + React, публичный сайт запускает существующий Noros Laravel 13 + Filament 5 в `public-site`. В общем docroot `backend/public/index.php` выбирает ровно один runtime до загрузки Composer. Список маршрутов приложения находится в `backend/bootstrap/application-path.php`. Это позволяет использовать платформу без обновления зависимостей финансового приложения и без смешения баз.

CMS использует приватный SQLite `public-site/database/site.sqlite`, cookie `norocel_site_session` и файловый cache/session. Публичная навигация не перезаписывает XSRF-cookie финансового приложения. Адаптер `CmsConfiguration` применяет стандартный выбор языка Noros к пути `/cms` после старта сессии; пакеты core не содержат условий Norocel. Кабинет отдаёт `noindex`; PWA работает на маршрутах приложения и не подменяет публичные страницы офлайн-оболочкой.

Для локальной работы нужен PHP 8.3+ с SQLite, Composer и Node. В `public-site` установить зависимости, создать локальную `.env` с абсолютным DB_DATABASE, сгенерировать APP_KEY, выполнить migrate и db:seed. Сборка приложения — `npm run build` в `frontend`, синхронизация темы — `node scripts/public-site-assets.mjs` из корня. `scripts/public-site-qa-router.php` используется исключительно локально с изолированным QA приложением на 8001; production использует Apache и общий dispatcher.

## Выпуск и восстановление

`scripts/package-public-site.py` собирает подготовленный no-dev runtime из `.runtime/public-site-release` и явный список файлов интеграции. В архив не входят `.env`, базы и пользовательские данные. Каждый файл и весь архив имеют SHA-256. `scripts/deploy-public-site-timeweb.sh` проверяет каталог и контрольные суммы, делает приватную резервную копию заменяемых файлов, создаёт отдельную CMS и проверяет неизменность финансовых данных и `.env`. При ошибке автоматически восстанавливает приложение. Он предназначен для первого размещения, обновления контента выполняются через CMS.

Обложки темы копируются также в CMS public disk, чтобы штатный редактор медиа мог сохранить их при редактировании. Публикуемые медиа доступны через `backend/public/site-media`, направленный на `public-site/storage/app/public`. База, credentials и runtime находятся вне docroot.

Локальные проверки: 46 backend-тестов (463 assertions), 4 frontend-теста, 5 тестов публичного сайта (294 assertions), 6 сценариев публичного сайта desktop/mobile, регистрация/подтверждение почты/восстановление пароля desktop/mobile. Проверены шесть ширин: 360/390/430/768/1024/1440. Снимки — `docs/qa/public-site-*.png`. Изолированная QA использует log mailer; продукционные тестовые письма и финансовые операции не создаются.

После размещения прошли четыре браузерных сценария desktop/mobile на живом домене и 45 HTTP-проверок: 27 локализованных страниц/статей, медиа и CMS-ресурсы, 404, sitemap, robots, private API, PWA, health. Проверен валидный сертификат (текущий срок до 04.12.2026, Timeweb показывает автопродление) и HTTP 301 на HTTPS. Владелец вошёл в стандартную CMS, переключил язык и сохранил главную без изменения текста. Существующая финансовая сессия сохранилась. Сервер сравнил контрольные суммы `.env` и всех строк финансовых таблиц до/после размещения — совпали. Результат: `docs/qa/public-site-live-checks.json`; снимок живой главной: `docs/qa/public-site-live.jpg`.

Финальная сборка также направляет уже авторизованного пользователя с `/login` и `/register` на `/app`; проверено в QA desktop/mobile и на живом сайте. После сохранения в CMS сервер подтвердил наличие всех девяти блоков главной, `index,follow` и исходного OpenGraph-изображения. Запись для других пользователей/групп у файлов выпуска отключена.
