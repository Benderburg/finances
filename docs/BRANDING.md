# Логотип Norocel

Источник — `logo.png` в корне репозитория. `npm run brand` в `frontend` генерирует SVG-логотипы для светлой/тёмной темы, знак N, анимированный лоадер, SVG/ICO-фавиконы, Apple Touch Icon и обычные/maskable PWA-иконки. Генерация также выполняется перед `npm run dev` и `npm run build`.

Надпись переводится в векторные контуры из исходного изображения. N, монетка и передняя стенка кармашка — отдельные SVG-слои; монетка падает, слегка отскакивает и скрывается за кармашком. При `prefers-reduced-motion: reduce` показывается статичный знак. Текст загрузки доступен скринридерам на выбранном языке.

Файлы синхронизируются в `backend/public/icons`, `frontend/public/icons` и `public-site/public/icons`. После сборки `node scripts/public-site-assets.mjs` синхронизирует CSS и OpenGraph-изображение публичного сайта в общий document root. Все ресурсы лоадера и логотипа входят в офлайн-кеш PWA; изменение ресурсов обновляет версию кеша.

## Публикация на Timeweb

GitHub Actions проверяет код и тесты. Push и успешный CI сами по себе не публикуют обновление на `norocel.noros.net`.

После `npm run build` в `frontend` и `node scripts/public-site-assets.mjs` выполнить `python scripts/package-branding.py`. Скрипт собирает архив с явным списком файлов логотипов, сборки, PWA и шаблонов сайта; `.env`, базы, vendor и пользовательские файлы в него не входят. В выводе указаны имя архива и SHA-256.

Загрузить архив в приватный `/home/c/ck85651/norocel`, проверить его SHA-256, извлечь `deploy-branding.sh` в `.deploy` и проверить через `bash -n`. Из каталога сайта выполнить `bash .deploy/deploy-branding.sh ИМЯ_АРХИВА SHA256`. Скрипт проверяет docroot и все файлы, сохраняет откат, публикует ресурсы, пересобирает Blade views и подтверждает неизменность настроек и базы CMS. Старые hashed JS/CSS остаются доступными.

Статические `backend/public/sw.js` и `manifest.webmanifest` переносятся в приватную копию отката: Timeweb кеширует статику на год, а Laravel обслуживает эти URL из `resources/pwa` с `no-cache`. Установка PWA запрашивает ресурсы с `cache: reload`, чтобы прежний HTTP-кеш не подменял новые HTML и иконки; версия кеша учитывает также код генератора service worker.

Перед сообщением об успешной публикации проверить живые `/ru`, `/login`, MIME и контрольные суммы SVG/PNG/ICO, новую версию `/sw.js` и `no-cache` для SW/manifest. Ответ `200` с HTML вместо SVG означает отсутствующий файл, а не успешную загрузку логотипа. Проверить также загрузку логотипа и лоадера в браузере.

Проверка: production-сборка и 4 frontend unit-теста, 5 тестов публичного сайта (294 assertions), 4 браузерных сценария кабинета (390/1440, светлая/тёмная темы). Локальная проверка брендинга подтвердила страницы сайта на 360/390/430/768/1024/1440, начальный лоадер до запуска React, положение монетки на этапах анимации, reduced motion и загрузку логотипа/иконок офлайн. Предпросмотр и результаты — `.runtime/branding/loader.gif` и `.runtime/branding/checks.json`.
