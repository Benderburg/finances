# Этап B — курсы и CSV

Реализация после приёмки этапа A, 2026-10-04. Новая миграция расширяет валюты до MDL/EUR/USD/RON и добавляет таблицы справочных курсов, CSV preview и квитанций импорта. Она не пересоздаёт workspace и не меняет существующие денежные значения. Обратное сужение enum намеренно запрещено: исправления выпускаются новой миграцией.

## Курсы BNM

Источник проверен по [официальной странице BNM](https://www.bnm.md/ro/content/ratele-de-schimb). Экспорт: `https://www.bnm.md/ro/official_exchange_rates?date=DD.MM.YYYY&get_xml=1`; XML `ValCurs@Date`, `Valute/CharCode`, `Nominal`, `Value`. Запрос выполняется сервером, connection timeout 2s, общий timeout 5s; redirect выключен. Парсер запрещает DOCTYPE/ENTITY и network entities, проверяет дату, уникальность и полный набор поддерживаемых иностранных валют. MDL всегда 1.

Номинал нормализуется без потери точности. В таблице сохраняются опубликованные nominal/value, SHA-256 XML, URL, дата запроса, дата публикации, время загрузки и неизменяемый номер версии. Повтор того же наблюдения не создаёт запись; исправленный курс создаёт новую версию. Положительный cache — 6 часов, ошибка — 2 минуты. Внешние запросы запрещены внутри DB transaction.

Расчёт: `source_minor × mdl_per_unit(source) / mdl_per_unit(target)`. Все четыре валюты имеют scale 2; каждая операция округляется HALF_UP один раз, затем значения суммируются произвольными целыми. Лимит отдельного денежного значения не ограничивает агрегат. Фактические exchange amounts/effective rate остаются независимыми.

- Dashboard: текущие остатки включённых счетов оцениваются на выбранную дату; default — сегодня в timezone владельца. Выбранная дата меняет оценку текущего остатка, а не превращает его в исторический остаток.
- Cash flow и budgets: курс на occurred_on каждой операции, включая расходы других валют; валюты и лимиты бюджетов сохраняются.
- Expenses: оценка каждой строки до группировки по категориям; исходные категории/валюты также доступны в API.
- Balance history: исходные ряды счетов сохраняются; отдельный суммарный ряд оценивается на дату каждой точки.

Допускается только предыдущий курс, не старше семи календарных дней. Метаданные содержат requested/effective dates, fallback, record ID и version. Будущие наблюдения не применяются задним числом. При отсутствии курса возвращаются `incomplete`, `missing`, исходные `unconverted` и `known_subtotal`. UI явно подписывает неполный расчёт; budget remaining не показывается как окончательный при отсутствии курса. Cache key включает валюту, период/фильтры, workspace revision, версии ставок и результат.

`GET /api/v1/fx/reference?date=YYYY-MM-DD` читает сохранённые наблюдения; `refresh=1` загружает выбранную дату вне финансовой транзакции. Dashboard/reports сами не ждут BNM. Кнопка загрузки обновляет дату оценки и отсутствующие даты операций выбранного месяца (до 32 дат за один проход); историю можно загрузить CLI. Quote — только ориентировочный preview без резервирования или изменения полей сохранённой операции.

```sh
php artisan norocel:fx-sync
php artisan norocel:fx-sync --from=2026-09-01 --to=2026-09-30
php artisan norocel:fx-sync --from=2026-09-01 --to=2026-09-30 --force
```

Один вызов CLI ограничен интервалом 366 дней. Daily cron на Timeweb использует `/opt/php8.5/bin/php`; день определяется в Europe/Chisinau. Время cron трактуется часовым поясом сервера. Логи — `storage/logs/fx-sync.log`, без финансовых данных.

## CSV

Export содержит весь журнал, включая voided, transfer/exchange и context IDs. UTF-8 BOM, CRLF, стандартное CSV quoting, decimal dot в основных единицах. Первая строка — `#norocel-csv,1,excel-safe` или `#norocel-csv,1,raw`; затем колонки из ТЗ и дополнительный `goal_completion_requested`. В safe-режиме все непустые пользовательские текстовые поля получают ведущий апостроф, включая уже начинающиеся апострофом; importer снимает ровно один префикс. Это предотвращает формулы Excel и сохраняет исходный текст при round trip.

Import — добавление, отдельно от JSON restore. До 5 MiB / 10 000 data rows. Preview сначала обнаруживает формат/encoding/delimiter и показывает образец; без `confirmed=true` не создаёт финансовые записи. Поддержаны UTF-8, Windows-1251/1250, UTF-16LE/BE, comma/semicolon/tab/pipe; пользователь подтверждает или перечитывает с другим форматом.

Банковский CSV: map date/amount/direction/currency/description/category/transaction_id, один выбранный счёт, категории по точному имени либо выбранные defaults для income/expense. Форматы дат: Y-m-d, d.m.Y, d/m/Y, m/d/Y; decimal dot/comma выбирается явно. Если direction не задан, положительные суммы считаются income, отрицательные — expense; это отдельно объясняется до подтверждения. Валюта обязана совпадать со счётом. Unknown/transfer/exchange directions и распознаваемые transfer descriptions отклоняются; пользователь также проверяет остальные строки, исключает обе стороны переводов и добавляет transfer вручную. Автоматической склейки нет.

Собственный CSV: account IDs сохраняются либо явно сопоставляются существующим счетам той же валюты; transfer/exchange импортируются как одна операция с двумя суммами. Категория должна однозначно совпасть по system code или точному имени. Goals/liabilities не создаются из CSV и не ищутся по имени. Отсутствующая связь даёт `CSV_CONTEXT_REQUIRES_JSON`; существующая проверяется теми же доменными ограничениями, settlement создаёт соответствующую связь и revision атомарно. Для полного восстановления сущностей и audit history нужен JSON backup.

UUID собственного экспорта и account-scoped уникальный bank transaction ID — строгие дубли. Hash account/date/type/amount/currency/нормализованного description — возможный дубль, который можно явно включить. Две одинаковые покупки внутри файла сохраняются, если обе выбраны и подтверждены. SHA-256 исходного upload + номер строки и строгие IDs сохраняются как уникальные квитанции; повтор того же файла не добавляет строки через новый preview/key. Квитанции сохраняются через JSON restore и несут workspace generation.

Preview истекает через 30 минут. Apply проверяет владельца, generation и workspace revision. Любая промежуточная финансовая команда требует нового preview. Один batch command вставляет выбранные строки и audit/context links, проверяет итоговые balances, затем сохраняет квитанции и ответ идемпотентности. Ошибка полностью откатывает пакет. Расход в начале файла может финансироваться доходом в конце; проверяется завершённый пакет.

UI удерживает неизвестный результат и исходный command key в памяти, блокирует изменение выбора до retry; reload не сохраняет private CSV draft. Нагрузочный benchmark 10 000 строк на Timeweb не выполнялся. Физические устройства и поведение разных версий Excel ещё требуют отдельной проверки.
